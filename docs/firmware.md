# MOTION-X firmware: build, upload, bench test

> **Not a medical device. Prototype. Use under supervision.**
> Do every first test with the motor **disconnected from the mechanism** and nobody on the machine.

The ESP32 sketch is in [`firmware/motionx/`](../firmware/motionx):

| File | What it is |
|---|---|
| `motionx.ino` | The firmware: Wi-Fi hotspot, web server, WebSocket ([protocol.md](protocol.md)), ESC, ramp, heartbeat timeout, IR remote, telemetry. |
| `config.h` | **Everything you calibrate**: pins, ESC pulse widths, ramp rates, IR key codes, Wi-Fi password, sensor switches. |
| `data/` | The web app, gzipped, for LittleFS. Generated by `npm run build:device` (not in git). |
| `../platformio.ini` | PlatformIO project (same sketch). |

## What the firmware does

- **Boots stopped.** The ESC gets `ESC_STOP_US` for `ESC_ARM_MS` (3 s) so it arms; speed commands are refused until then (`fault: "esc_not_armed"`).
- **Ramps every change.** Speed-up is limited to 25 % of full output per second, slow-down to 50 %/s. Stopped → level 3 takes at least 4 s.
- **Hard ceiling.** No pulse above `ESC_MAX_US_LIMIT` (1300 µs by default) is ever sent, whatever the levels say.
- **Heartbeat timeout.** If the app started the motor and sends nothing for 2 s, the motor ramps to a stop and `fault: "heartbeat_timeout"` is set.
- **Emergency stop** cuts output instantly and latches until `reset` from the app (or a power cycle). The IR remote cannot clear it.
- **IR remote** keeps working: `0` stop (always wins), `1`/`2`/`3` levels. IR control does not need the app and has no timeout.
- **Telemetry stubs:** hall-sensor rpm (`USE_HALL_RPM`) and INA219 current (`USE_INA219`). When off or missing, the app receives `null` and estimates.
- **Wi-Fi hotspot** `MOTION-X` at `http://192.168.4.1`, with DNS for any name and "internet OK" answers so phones stay connected.
- **`GET /api/state`** returns the current state JSON (handy with `curl` on the bench).

## Wiring (defaults in `config.h`)

| Part | ESP32 pin | Notes |
|---|---|---|
| ESC signal (white/yellow) | GPIO 18 | **Connect ESC ground to ESP32 GND** (common ground). |
| ESC +5 V (BEC red wire) | not connected | Power the ESP32 from USB or its own 5 V supply unless you know the BEC is clean 5 V. |
| IR receiver (VS1838B/TSOP38238) OUT | GPIO 4 | VCC → 3.3 V, GND → GND. |
| Hall sensor (optional) | GPIO 27 | Open-collector to GND, internal pull-up used. Set `USE_HALL_RPM 1`. |
| INA219 (optional) | SDA 21, SCL 22 | 3.3 V supply. Set `USE_INA219 1` and install "Adafruit INA219". |

Change any pin in `config.h` to match your existing wiring (for example the IR pin from your current remote sketch).

## 1. Build the web app for the device

From the repository root:

```bash
npm install
```
```bash
npm run build:device
```

This writes `firmware/motionx/data/` (about 50 KB gzipped). In this build Demo mode is **off** by default.

## 2a. Flash with the Arduino IDE 2

1. **File → Preferences → Additional boards manager URLs:** `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. **Boards Manager:** install **esp32 by Espressif Systems** (3.x).
3. **Library Manager:** install
   - **ESP Async WebServer** (by ESP32Async)
   - **Async TCP** (by ESP32Async)
   - **ArduinoJson** (by Benoit Blanchon, 7.x)
   - **IRremote** (by Armin Joachimsmeyer, 4.x)
4. Open `firmware/motionx/motionx.ino`.
5. **Tools:** Board **ESP32 Dev Module**, Partition Scheme **Default 4MB with spiffs**, Port **your COM port**.
6. **Upload** the sketch.
7. **Upload the web app:** install the [arduino-littlefs-upload](https://github.com/earlephilhower/arduino-littlefs-upload) plugin (copy the `.vsix` to `~/.arduinoIDE/plugins/`, restart the IDE). Close the Serial Monitor, press **Ctrl+Shift+P** → **Upload LittleFS to Pico/ESP8266/ESP32**. It uploads `firmware/motionx/data/`.

## 2b. Flash with arduino-cli (exact commands, Windows)

The Arduino IDE ships `arduino-cli`. Replace `COM5` with your port (`arduino-cli board list`).

```bash
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
```
```bash
arduino-cli core update-index && arduino-cli core install esp32:esp32
```
```bash
arduino-cli lib install "ESP Async WebServer" "Async TCP" ArduinoJson IRremote
```
```bash
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/motionx
```
```bash
arduino-cli upload -p COM5 --fqbn esp32:esp32:esp32 firmware/motionx
```

Web app (LittleFS image) with the tools that come with the ESP32 core. The default 4 MB partition table puts the filesystem at `0x290000`, size `0x160000`:

```bash
mklittlefs -c firmware/motionx/data -p 256 -b 4096 -s 0x160000 littlefs.bin
```
```bash
esptool --chip esp32 --port COM5 --baud 921600 write_flash 0x290000 littlefs.bin
```

`mklittlefs` and `esptool` are in `%LOCALAPPDATA%\Arduino15\packages\esp32\tools\` after the core install (older esptool versions name it `esptool.py` / `write_flash`; newer ones accept `write-flash`).

```

[esc] arming: holding 1000 us for 3000 ms
[wifi] AP "MOTION-X" at 192.168.4.1

[esc] armed
```

If you see `[fs] LittleFS not found`, upload the web app (step 2).

## 4. Calibrate

**ESC throttle range** (once, per the ESC manual): many ESCs learn min/max by powering up with full throttle then dropping to minimum. Do this with a servo tester or the ESC's own procedure, motor unloaded. The firmware itself never sends more than `ESC_MAX_US_LIMIT`.

**Speed levels** (`LEVEL_PULSE_US` in `config.h`): defaults are deliberately low (1080 / 1120 / 1160 µs).
1. With the motor unloaded, set level 1 from the app and watch the motor.
2. If it does not turn, raise `LEVEL_PULSE_US[1]` by 10–20 µs, re-upload, repeat. Stop at the lowest value that turns smoothly.
3. Set levels 2 and 3 so the crank speeds are roughly 15 / 25 / 35 rpm once coupled (the app's cycle estimate assumes these).
4. Keep `ESC_MAX_US_LIMIT` just above your level 3 value.

**IR keys:** press each remote key with the Serial Monitor open. You will see `[ir] IR command 0x16 (protocol NEC)`. Put the codes for your 0/1/2/3 keys into `IR_KEY_0..3`.

## 5. Bench test checklist

Tick every line in order. **Stop at the first failure** and fix it before going on.

### A. Electronics only (motor unplugged from the ESC)
- [ ] A1. ESP32 boots; serial shows the banner, `arming`, then `[esc] armed` about 3 s later.
- [ ] A2. Phone sees Wi-Fi **MOTION-X**, joins with the password from `config.h`.
- [ ] A3. `http://192.168.4.1` opens the app; the badge shows **Connected** (not Demo mode).
- [ ] A4. `curl http://192.168.4.1/api/state` returns `"level":0,"running":false`.
- [ ] A5. With a servo tester/oscilloscope on GPIO 18: 50 Hz, 1000 µs at idle.
- [ ] A6. Press Start at level 3: pulse rises **gradually** (≥ 4 s) to `LEVEL_PULSE_US[3]`, never above `ESC_MAX_US_LIMIT`.
- [ ] A7. Emergency Stop in the app: pulse drops to 1000 µs **immediately**; app shows "Emergency stop is on"; Start is refused until Reset.

### B. Motor on the bench, NOT coupled to the mechanism
Clamp the motor firmly. Nothing attached to the shaft. Hands clear. Supervisor present.
- [ ] B1. Power cycle with the app open: motor stays still until a command (boots stopped).
- [ ] B2. Level 1 → motor speeds up smoothly; level 2 and 3 step up smoothly; no jerk.
- [ ] B3. Stop motor → ramps down to stopped within about 2 s.
- [ ] B4. Emergency Stop from **another tab** (e.g. Settings): motor stops at once.
- [ ] B5. **Heartbeat:** at level 1, turn the phone's Wi-Fi off. Motor stops within ~2 s (+ ramp). Wi-Fi back on: app shows "The motor stopped for safety"; Start works again.
- [ ] B6. **Page closed:** at level 1, close the browser tab or lock the phone. Motor stops within ~2 s.
- [ ] B7. **IR:** keys 1/2/3 set the level, key 0 stops. Works with no phone connected and keeps running (no timeout).
- [ ] B8. IR key 0 stops a motor that the app started. IR keys cannot clear an emergency stop.
- [ ] B9. Run 5 minutes at level 3: ESC and motor only warm; no brown-outs or ESP32 resets in the log.
- [ ] B10. Telemetry: with sensors off, the app shows "no sensor"; with a sensor enabled, values look plausible.

### C. Coupled to the mechanism (no person on it)
- [ ] C1. Mains/battery switch within reach of the supervisor.
- [ ] C2. Repeat B2, B3, B4, B5 with the mechanism coupled and empty. Note the crank rpm at each level.
- [ ] C3. Run a full 2-minute session from the app (Warm-up pattern). It completes, stops, and is saved.

### D. With a volunteer (only after A–C pass)
- [ ] D1. Supervisor present, volunteer briefed: stop = red button / IR key 0.
- [ ] D2. Level 1 only, 2 minutes. Ask for comfort score. Stop immediately on any discomfort.

Record date, firmware version, `LEVEL_PULSE_US` values and who checked each section.

## Troubleshooting

| Symptom | Check |
|---|---|
| App says "Connection lost" every few seconds | Phone switched to mobile data: turn mobile data off, or answer "stay connected" to "no internet". |
| Page loads but stays "Connecting" | Opened over HTTPS (e.g. Vercel link): use `http://192.168.4.1`. |
| `[fs] LittleFS not found` | Upload the web app (step 2), with the Default 4MB partition scheme. |
| Motor twitches at boot | ESC not calibrated / arming: increase `ESC_ARM_MS`, check common ground. |
| Motor never turns | Raise `LEVEL_PULSE_US[1]` gradually; confirm ESC arming beeps. |
| IR does nothing | Check `PIN_IR`, read codes in Serial Monitor, update `IR_KEY_*`. |
| ESP32 resets when the motor starts | Power the ESP32 separately from the motor supply; add a bulk capacitor on the ESC supply. |
